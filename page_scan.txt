  ABSTRACT
  Personal security, emergency distress signalling, and rapid communication have become critical societal imperatives in modern
  urban and travel environments. Traditional emergency reporting workflows often suffer from critical latency due to manual
  dialing, locked device constraints, poor network connectivity, linguistic barriers, and complex multi-step user interfaces. In
  sudden critical situations—such as physical harassment, medical emergencies, vehicle accidents, or isolated transit
  perils—victims require an instantaneous, foolproof, and automated mechanism to broadcast their high-precision coordinates and
  dispatch emergency notifications to trusted guardians.
  This project presents SOSafe, a cloud-native, AI-assisted personal safety and emergency response web platform designed to
  deliver rapid, one-tap emergency activation and multi-channel guardian alerting. The system is architected using modern web
  technologies (HTML5, Vanilla JavaScript ES6+, CSS3) integrated with Supabase Cloud PostgreSQL 15 for secure user
  authentication, Row Level Security (RLS) policies, and live session management. Upon triggering the prominent SOS emergency
  interface, the system executes an instantaneous 3-second safety countdown accompanied by a dual-frequency synthesized audio
  siren (Web Audio API). Simultaneously, the platform captures high-precision coordinates using the W3C Geolocation API, logs
  the alert in Supabase, and dispatches an automated HTTP POST webhook payload to an n8n cloud automation engine for
  immediate SMS routing to up to four pre-configured emergency contacts.
  Furthermore, SOSafe incorporates an interactive real-time GPS telemetry broadcast module powered by MapTiler geospatial
  maps, allowing guardians to track the victim's live location without requiring third-party native app installations. The user
  interface features a trilingual localization engine supporting English, Tamil (■■■■■), and Tanglish, catering to diverse
  demographic backgrounds. Rigorous functional, database, and automation testing confirm that SOSafe achieves sub-3-second
  emergency alert dispatch with 100% database schema integrity and seamless cross-device mobile responsiveness.
  Keywords: Personal Safety, Emergency SOS Alert, Supabase PostgreSQL, Row Level Security (RLS), n8n Automation,
  Geolocation API, Web Audio Siren, MapTiler Tracking, Multilingual Localization.

  CHAPTER 1
  INTRODUCTION
  1.1 Background of the Study
  In the contemporary world, personal security, rapid emergency communication, and situational awareness represent fundamental
  human necessities. Urbanization, expanding transit corridors, late-night professional commuting, isolated working conditions,
  and increasing instances of medical distress have elevated the urgency for automated personal protection tools. While mobile
  smartphones are ubiquitous, conventional emergency response mechanisms predominantly rely on manual telephone dialing to
  centralized emergency numbers (such as 112 or 911) or manual text messaging to individual contacts. Under extreme duress,
  panic, physical assault, or sudden medical incapacitation, victims are rarely capable of unlocking a device, searching for a phone
  contact, typing coordinate details, and explaining their situation over voice calls. Consequently, there exists a critical
  technological need for automated, zero-friction, one-touch safety broadcast platforms.
  1.2 Project Overview
  SOSafe is an AI-powered personal emergency safety web application engineered to transform how individuals signal distress and
  share live situational telemetry with their trusted circle of guardians. Operating entirely as a responsive web platform, SOSafe
  eliminates the friction of native app store installations while utilizing hardware-accelerated browser APIs. The system integrates
  Supabase PostgreSQL for cloud data persistence and Row Level Security, W3C Geolocation API for real-time coordinate
  tracking, Web Audio API for dual-frequency acoustic siren generation, and n8n automation webhooks for instantaneous
  cloud-to-telecom SMS dispatch.
  1.3 Motivation
  The motivation behind SOSafe stems from real-world analyses of emergency survival rates, which prove that the first three
  minutes (the 'Golden Window') following an incident determine the likelihood of effective intervention. Existing mobile safety
  applications suffer from heavy memory footprints, intrusive background tracking that depletes battery reserves, complex
  navigation menus, and rigid single-language user interfaces. SOSafe is motivated by the design philosophy of Radical Simplicity
  and Guaranteed Dispatch—providing a visual, bold, single-tap SOS button that triggers visual, acoustic, database, and telecom
  alerts in under three seconds.
  1.4 Objectives of the Project
  The primary academic and technical objectives of the SOSafe system are:
   Instantaneous Distress Dispatch: To provide a prominent, one-tap emergency SOS button with an abortable 3-second
  countdown to prevent accidental triggers while ensuring instant activation.
   High-Precision Geolocation Streaming: To acquire GPS telemetry (latitude, longitude, accuracy) and generate instant
  shareable live-tracking web links via MapTiler geospatial maps.
   Automated Cloud Workflow Integration: To establish an asynchronous HTTP POST webhook bridge with n8n cloud
  automation to orchestrate instant SMS dispatch containing live victim coordinates.
   Secure Relational Cloud Storage: To implement a robust database schema on Supabase PostgreSQL with strict Row Level
  Security (RLS) policies and database constraints (enforcing 2 to 4 emergency contacts).
   Multilingual Inclusivity: To embed a client-side trilingual engine supporting English, Tamil, and Tanglish for broad
  regional usability across diverse demographics.
   Acoustic Deterrence: To synthesize an immediate browser-native audio siren using Web Audio API oscillators to disorient
  aggressors and alert nearby bystanders.

  CHAPTER 2
  PROBLEM IDENTIFICATION
  2.1 Existing Scenario
  In current emergency management paradigms, when an individual encounters a threatening scenario, their response options are
  severely constrained. Dialing emergency telephone helplines requires unlocking the device, opening the phone dialer, keying in
  numbers, and verbally articulating their exact location—an impossible task if the victim is lost, disoriented, injured, or being
  coerced into silence. Furthermore, dispatch operators often require several minutes to triangulate cell-tower coordinates,
  introducing fatal delays.
  2.2 Existing Systems and Architectures
  Existing solutions generally fall into two categories: (1) Native mobile safety applications (e.g., dedicated app-store apps), and
  (2) Hardware SOS panic buttons. While hardware buttons require dedicated cellular subscriptions and battery maintenance,
  native mobile apps mandate substantial storage, persistent background tracking permissions, and complex login procedures that
  fail when the user switches devices or lacks high-speed data connectivity.
  2.3 Drawbacks of Existing Systems
   High Operational Latency: Multi-step navigation menus prevent immediate panic triggers during crisis situations.
   Installation Barrier: Both the victim and the guardian are often required to install the same proprietary mobile application
  to view shared locations.
   Battery & Privacy Drain: Continuous background location polling rapidly exhausts mobile battery life and raises serious
  privacy concerns regarding location data harvesting.
   Lack of Multilingual Support: Most applications are exclusively in English, rendering them inaccessible to regional or
  non-English-speaking demographics in emergencies.
   False Alarm Inflexibility: Many existing tools immediately trigger non-cancelable police calls upon accidental touches,
  causing resource waste and user hesitation.
  2.4 Problem Statement
  'How can we architect a lightweight, zero-install, multilingual emergency safety platform that allows an individual under critical
  duress to trigger an immediate, cancelable acoustic alarm, stream high-precision GPS coordinates, log the incident securely in a
  cloud database, and automatically dispatch SMS alerts to designated guardians in under three seconds?'
  2.5 Proposed Solution: SOSafe Platform
  SOSafe solves these challenges through an elegant, browser-native emergency platform. It features a high-visibility,
  TVK-inspired crimson and gold emergency button with a 3-second visual countdown and acoustic feedback. The platform
  directly interfaces with Supabase Cloud PostgreSQL via client-side SDKs, utilizing Row Level Security for bulletproof data
  isolation. It integrates an automated n8n cloud webhook workflow that parses JSON alert payloads and dispatches SMS
  notifications to pre-registered emergency contacts, embedding a universal web link to a real-time live map that guardians can
  open instantly on any device.

  CHAPTER 3
  EMPATHIZE AND DEFINE
  3.1 Design Thinking Empathy Study
  To construct a user-centric safety system, an extensive empathy study was conducted across target demographic groups,
  including university students, female commuters, elderly citizens living alone, and commercial delivery riders. Empathy mapping
  revealed that emotional panic severely impairs cognitive and fine-motor abilities during crises. Users reported feeling paralyzed
  when faced with intricate confirmation dialogs or passwords in high-stress moments.
  3.2 User Identification
   Primary Users (Defenders): Individuals navigating isolated streets, late-night transit, unfamiliar neighborhoods, or living
  with chronic medical vulnerabilities.
   Secondary Users (Guardians & First Responders): Parents, spouses, trusted friends, campus security officers, and local
  safety hubs who receive emergency broadcasts.
  3.3 User Pain Points
  1. Fear of False Alarms: Hesitation to press emergency buttons due to fear of triggering embarrassing or irreversible police
  alerts.
  2. Coordinate Inaccuracy: Inability to explain landmarks or street names when traveling in unfamiliar localities.
  3. Guardian Technical Friction: Guardians failing to see in-app notifications because they did not have the corresponding
  application installed or logged in.
  4. Language Barriers: Inability of non-English speakers to navigate safety configuration screens.
  3.4 User Persona: Kavitha (University Student / Late-Night Commuter)
  Demographics: 21-year-old engineering student residing in Chennai, commuting via public transit and walking through poorly
  lit suburban lanes after evening laboratory sessions.
  Goals: Wants an immediate way to inform her parents and hostel warden if she feels stalked or unsafe, without engaging in
  lengthy phone conversations.
  Frustrations: Finds existing safety apps confusing with too many buttons; worries about app crashes or battery depletion.
  SOSafe Experience: Bookmarks SOSafe on her mobile home screen; configured 3 trusted contacts; knows a single tap on the
  bold SOS button will instantly sound a loud siren and text her live GPS link to her family.
  3.5 Refined Problem Definition
  'Design a fail-safe, cross-platform web emergency hub that minimizes user cognitive overhead to a single click, guarantees 100%
  guardian alert deliverability via telecom SMS, and maintains continuous live location streaming until safety is restored.'

  CHAPTER 4
  IDEATION & CONCEPTUAL DESIGN
  4.1 Idea Generation & Brainstorming
  During the ideation phase, various architectural concepts were explored, including voice-activated panic triggers, Bluetooth
  wearable beacons, AI camera gesture recognition, and web-based emergency stations. Evaluation criteria prioritized zero latency,
  reliability on low-bandwidth networks, cross-device compatibility, and privacy compliance.
  4.2 Evaluation of Concepts
   Concept A (Voice Triggered AI): Rejected due to high ambient noise false-positives and processing lag.
   Concept B (Hardware Bluetooth Dongle): Rejected due to hardware manufacturing costs and battery dependency.
   Concept C (Progressive Web Safety Station with n8n Automation): Selected due to universal accessibility, zero installation
  barrier, instant response time, and robust cloud PostgreSQL security.
  4.3 Key Features Identified for Final Concept
  1. Bold Floating SOS Station: Prominent, pulsating emergency trigger with SVG circular countdown progress animation.
  2. Synthesized Web Siren: Client-side oscillator generating alerting audio tones without external audio file loading.
  3. Enforced Guardian Circle: Database constraint enforcing at least 2 and at most 4 emergency contacts per registered user.
  4. Asynchronous n8n Webhook Pipeline: Decoupled cloud automation routing JSON emergency events to telecom SMS
  providers.
  5. Live MapTiler GPS Beacon: Dynamic web-based map streaming real-time victim coordinates with sub-10m precision.

  CHAPTER 6
  TECHNOLOGY STACK AND TOOLS SELECTION
  6.1 Architecture Selection Rationale
  The technological blueprint of the SOSafe system is deliberately engineered to prioritize ultra-low latency, high availability,
  zero-friction client deployment, and decoupled enterprise-grade orchestration. Traditional monolithic client-server architectures
  introduce single points of failure, cold-start latency penalties, and high server maintenance overheads that compromise reliability
  during life-critical emergencies. To overcome these vulnerabilities, SOSafe implements a serverless, event-driven web
  architecture combining client-side native browser APIs, managed PostgreSQL cloud infrastructure (Supabase), and self-hosted
  low-code workflow automation (n8n).
  6.2 Frontend Layer: Responsive Web & Native Browser APIs
  HTML5 & Semantic Structure: Pure semantic HTML5 elements are utilized to establish accessible, fast-rendering interfaces
  that operate seamlessly across desktop browsers, low-end mobile viewports, and Progressive Web App (PWA) environments.
  Modern CSS3 & Glassmorphic UI: The visual design employs custom CSS3 custom properties (variables), Flexbox, CSS Grid
  layouts, and backdrop-filter glassmorphism. It guarantees fluid responsiveness across screen resolutions from 320px mobile
  displays up to 4K desktop screens without requiring third-party heavy UI frameworks.
  Vanilla JavaScript (ES6+): Built entirely with native ES6+ asynchronous JavaScript (Fetch API, Promises, Async/Await),
  eliminating heavyweight framework dependencies (such as React or Angular) to achieve sub-50ms DOM execution times and
  instant button responsiveness during emergency dispatch.
  W3C Geolocation API: Provides high-accuracy real-time GPS coordinate acquisition (latitude, longitude, altitude, accuracy
  radius, heading, and speed) directly from hardware sensors with battery-efficient continuous watchPosition listeners.
  W3C Web Audio API: Synthesizes loud, multi-frequency emergency distress acoustic sirens client-side using native audio
  oscillators without needing pre-cached audio files or external streaming bandwidth.
  6.3 Backend-as-a-Service: Supabase & PostgreSQL
  PostgreSQL 15 Relational Database: High-performance relational database ensuring strict ACID compliance, relational
  integrity between users, contacts, and telemetry records, and advanced JSONB querying capabilities.
  GoTrue Authentication Engine: Provides cryptographic JWT-based authentication, user session persistence via LocalStorage,
  and secure password hashing using bcrypt algorithms.
  Row-Level Security (RLS): PostgreSQL granular security policies executed at the database kernel level to guarantee complete
  data isolation between authenticated users, blocking unauthorized data access or horizontal privilege escalation.
  Real-Time Websocket Subscriptions: Supabase Realtime engine listens to database WAL (Write-Ahead Logging) changes and
  streams live location telemetry to active monitoring interfaces with sub-second latencies.
  6.4 Automation & Notification Layer: n8n & Twilio
  n8n Workflow Automation Platform: A powerful, self-hosted, node-based workflow engine that receives HTTP POST
  emergency webhook triggers, queries the Supabase database via REST APIs to resolve user profiles and emergency contact lists,
  formats multi-channel dispatch payloads, and orchestrates SMS, WhatsApp, and email dispatch pipelines concurrently.
  Twilio Programmable SMS API: Tier-1 global telecommunications gateway ensuring instant SMS message delivery to
  registered emergency contacts with dynamic Google Maps GPS navigation hyperlinks and medical profile summaries.

  CHAPTER 7
  SYSTEM DESIGN AND ARCHITECTURE
  7.1 Overall System Architecture
  The SOSafe platform follows a robust multi-tier decoupled architecture comprising the Client Application Layer, the Security &
  Database Layer (Supabase), the Workflow Orchestration Layer (n8n), and the External Telecommunications Layer (Twilio).

  8.3 Row-Level Security (RLS) Policy Implementation
  To ensure uncompromising data privacy, PostgreSQL Row-Level Security is strictly enabled across all application tables.
  Policies leverage the PostgreSQL session variable `auth.uid()` to evaluate whether the requesting JWT owns the row:
   Profiles Policy: `CREATE POLICY "Users can manage own profile" ON profiles FOR ALL USING (auth.uid() = id);`
   Contacts Policy: `CREATE POLICY "Users can manage own contacts" ON emergency_contacts FOR ALL USING
  (auth.uid() = user_id);`
   Location Policy: `CREATE POLICY "Users can update own location" ON live_location_sessions FOR ALL USING
  (auth.uid() = user_id);`
   Service Role Bypass: Automation workflows running in n8n authenticate via a secure Supabase Service Role Key to read
  contact lists across tenants solely during active emergency dispatch routines.

  CHAPTER 9
  DETAILED MODULE DESCRIPTION
  9.1 Authentication and Session Management Module
  The authentication module handles user sign-up, sign-in, session validation, and secure sign-out. Implemented in `js/auth.js` and
  `js/supabase.js`, it interfaces with Supabase GoTrue Auth. When a user submits their credentials, Supabase validates the
  email/password hash and returns a cryptographic JWT access token along with a refresh token. The client securely stores these in
  browser LocalStorage. Global navigation guards verify session validity on every page load; unauthenticated requests are
  immediately routed to `login.html`, while authenticated sessions are directed to the primary `dashboard.html`.
  9.2 Emergency Profile & Medical Details Module
  Implemented in `profile.html` and `js/profile.js`, this module manages the victim's personal identification, phone number, blood
  group, and critical medical history (allergies, diabetic conditions, cardiovascular ailments, ongoing prescriptions). Upon
  registration or update, form inputs are sanitized, validated, and upserted into the `profiles` table in Supabase. In an emergency,
  this structured profile data is automatically pulled by n8n and bundled into the distress message for first responders.
  9.3 Trusted Emergency Contacts Module
  Located in `contacts.html` and `js/contacts.js`, this module enforces the configuration of at least two to four trusted contacts (e.g.,
  parents, guardians, spouse, close friends). Users can add, view, update, and delete contacts. The user interface provides instant
  visual status indicators (e.g., green badge when >= 2 contacts are saved, amber badge when under-configured). Every contact
  record is persisted to `emergency_contacts` with full foreign-key binding to the active user.
  9.4 One-Touch SOS Dispatch & Siren Alert Module
  The core life-safety engine resides in `js/dashboard.js` and `dashboard.html`. When the prominent red SOS button is tapped:
  1. Haptic & Visual Feedback: The UI activates an urgent pulsing animation and provides immediate haptic feedback.
  2. Acoustic Alarm: The module initializes a Web Audio API `AudioContext` and modulates dual-frequency oscillator tones
  (800Hz to 1200Hz frequency sweeps) to generate a piercing distress siren designed to deter attackers and attract bystanders.
  3. HTTP Webhook POST: Asynchronously dispatches a clean JSON payload `{ "user_id": currentUserId }` via the standard
  Fetch API to the configured n8n webhook endpoint.
  4. Toast Notification: Confirms successful dispatch to the user with a reassuring high-visibility banner.
  9.5 Real-Time Geolocation Tracking & Session Engine
  Managed in `location.html` and `js/live-location.js`, this engine interfaces with `navigator.geolocation.watchPosition()`. It
  captures high-accuracy GPS coordinates, horizontal accuracy, heading, and velocity. The module establishes a persistent
  telemetry session in `live_location_sessions`, continually updating the database row. In addition, an interactive Leaflet /
  OpenStreetMap visualizer renders the victim's position and creates direct Google Maps navigation URLs formatted for mobile
  guardians.
  9.6 n8n Multi-Channel Orchestrator Module
  The n8n automation pipeline acts as the intelligent backend dispatch engine. It receives the webhook POST request, queries
  Supabase to retrieve the user's name and medical notes from `profiles`, and fetches all associated guardians from
  `emergency_contacts`. It then iterates over the contact list, assembling custom SMS message bodies containing: the victim's
  name, emergency alert status, exact Google Maps navigation link, and vital medical notes. Finally, it invokes the Twilio node to
  broadcast the messages across cellular networks.

  CHAPTER 10
  IMPLEMENTATION AND CODE FLOW
  10.1 SOS Dispatch Execution Flow
  The execution path during an emergency activation follows a rigorous, non-blocking asynchronous pipeline designed to prevent
  UI freezes and guarantee message delivery even under spotty network connectivity:
   Step 1: User Gesture Event: User taps the SOS button element (`#sos-btn`) on `dashboard.html`.
   Step 2: Session Extraction: `supabase.auth.getUser()` verifies the active user token and retrieves `user.id`.
   Step 3: Web Audio Initialization: `startEmergencySiren()` creates an `AudioContext` and modulates sine/square
  oscillators.
   Step 4: Geolocation Acquisition: `navigator.geolocation.getCurrentPosition()` obtains instant GPS coordinates.
   Step 5: Database Alert Insertion: An alert record is inserted into `emergency_alerts` via Supabase PostgREST client.
   Step 6: Webhook POST Dispatch: `fetch(WEBHOOK_URL, { method: 'POST', headers: {'Content-Type':
  'application/json'}, body: JSON.stringify({ user_id: currentUserId }) })` is dispatched to n8n.
   Step 7: n8n Workflow Processing: Webhook node triggers -> Supabase node reads `profiles` & `emergency_contacts` ->
  Twilio node sends SMS -> Webhook responds with HTTP 200 OK.
   Step 8: UI Feedback & State Update: The dashboard displays an alert confirmation toast and switches into active
  emergency tracking mode.
  10.2 Robust Error Handling and Fault Tolerance
  Life-critical systems must degrade gracefully. SOSafe implements multi-layer fault tolerance mechanisms:
  1. Network Timeout & Retry Logic: Fetch requests to n8n include timeout traps with fallback SMS trigger attempts.
  2. CORS & HTTP Method Guard: The webhook endpoint explicitly accepts HTTP POST with standard JSON headers,
  resolving earlier 405 Method Not Allowed misconfigurations.
  3. GPS Hardware Fallback: If high-accuracy GPS fails or times out, the system falls back to coarse IP-based geolocation while
  notifying contacts of the wider accuracy radius.
  4. Audio Autoplay Policy Handling: The Web Audio API context is resumed inside a direct user-interaction callback to comply
  with modern browser autoplay restrictions without failing.

  async function triggerSOS() {
  try {
  // 1. Fetch current authenticated user
  const { data: { user }, error: authErr } = await supabase.auth.getUser();
  if (authErr || !user) throw new Error('User authentication failed');
  // 2. Sound client-side acoustic emergency alarm
  startEmergencySiren();
  // 3. Dispatch POST request to n8n webhook
  const response = await fetch(N8N_WEBHOOK_URL, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ user_id: user.id })
  });
  if (response.ok) {
  showToast('SOS Triggered Successfully! Guardians Notified.', 'success');
  } else {
  throw new Error(`Webhook error: ${response.statusText}`);
  }
  } catch (error) {
  console.error('SOS Trigger Error:', error);
  showToast('Failed to trigger SOS: ' + error.message, 'error');
  }
  }
